## Kesimpulan Kelompok

Untuk Sistem Data Kependudukan, kelompok merekomendasikan **Hybrid Cloud**. Data utama seperti NIK, alamat, dan biometrik tetap disimpan dan diproses pada infrastruktur Private Cloud yang dikendalikan pemerintah. Komponen yang menghadapi permintaan berubah-ubah, seperti API Gateway dan layanan verifikasi tanpa penyimpanan data utama, dapat ditempatkan pada lingkungan Public atau Community Cloud yang elastis. Komponen tersebut hanya meneruskan permintaan terautentikasi dan memberikan hasil sesuai kewenangan, tanpa membuka akses langsung ke database inti.

Pembagian ini menjaga kendali negara atas data sensitif sekaligus membantu melayani akses dari ribuan instansi dan lonjakan permintaan pada musim pemilu atau pendaftaran sekolah. Rancangan tersebut sejalan dengan karakteristik cloud menurut NIST: administrator dapat menyediakan sumber daya sesuai kebutuhan, layanan diakses melalui jaringan dengan kontrol keamanan, sumber daya digunakan bersama secara terkelola, kapasitas layanan dapat disesuaikan, dan pemakaian dapat dipantau untuk perencanaan serta efisiensi.

Untuk Service Model, database inti dan layanan internal menggunakan **IaaS** pada infrastruktur pemerintah agar pengelolaan server, jaringan, penyimpanan, dan keamanannya tetap berada dalam kendali negara. Portal publik dan API Gateway menggunakan **PaaS** agar pengelolaan aplikasi lebih sederhana dan kapasitasnya dapat disesuaikan. Portal maupun instansi tidak memperoleh akses langsung ke database. Permintaan harus melewati layanan perantara dengan autentikasi, otorisasi, pembatasan laju, serta respons yang hanya memuat informasi sesuai kebutuhan.

Risiko utama rancangan ini meliputi keterbatasan kapasitas saat permintaan melonjak, penyalahgunaan akun atau hak akses instansi mitra, serta gangguan pada pusat data pemerintah. Mitigasinya mencakup perencanaan kapasitas, load balancing, autoscaling pada layanan aplikasi, antrean dan pembatasan permintaan, autentikasi multifaktor, prinsip least privilege, pemantauan dan audit, serta pusat data cadangan dengan prosedur failover yang diuji berkala.

Kelompok tidak memilih **Private Cloud murni** karena kapasitas fisiknya dapat membatasi rapid elasticity. Menyediakan perangkat untuk beban puncak sepanjang tahun berisiko menyebabkan over-provisioning, sedangkan penambahan perangkat melalui pengadaan pemerintah dapat memerlukan waktu. Hybrid Cloud memberi ruang untuk menangani lonjakan pada lapisan layanan tanpa memindahkan database utama dari infrastruktur yang dikendalikan pemerintah. Skenario tandingannya adalah menyediakan server cadangan khusus pada Private Cloud. Cara itu dapat menambah kapasitas, tetapi tetap memerlukan pengadaan dan pemeliharaan kapasitas yang jarang dipakai, sehingga tidak sepenuhnya menyelesaikan keterbatasan elastisitas dan efisiensi.
